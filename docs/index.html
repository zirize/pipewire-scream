Scream sender for PipeWire

A virtual audio sink that transmits everything played to it over the network as raw PCM — the Linux/PipeWire counterpart of the Windows Scream driver.

Source on GitHub The Scream project screamplay (CLI player)
AI-generated code. This module was produced with GitHub Copilot CLI with minimal human intervention. It is tested and working on PipeWire 1.0.5, but review the code before using it in production. Bug reports and code reviews are especially welcome. No warranty — see the licence.

What it does

Audio played to the virtual sink is transmitted as raw PCM over UDP — multicast by default (239.255.77.77:4010), unicast on request — to any Scream receiver on the network. It is the Linux/PipeWire equivalent of the Windows Scream driver, so existing receivers work unchanged.

  • Virtual audio sink in PipeWire
  • Multicast and unicast
  • Configurable sample rate, bit depth and channel count
  • Low latency, stable over long playback

Build

Needs PipeWire ≥ 0.3, CMake ≥ 3.10 and a C11 compiler.

# Ubuntu/Debian
sudo apt-get install libpipewire-0.3-dev pipewire cmake build-essential
# Fedora/RHEL
sudo dnf install pipewire-devel cmake gcc
# Arch
sudo pacman -S pipewire cmake gcc

git clone https://github.com/zirize/pipewire-scream.git
cd pipewire-scream
mkdir build && cd build
cmake .. && make && sudo make install

Loading it automatically

mkdir -p ~/.config/pipewire/pipewire.conf.d/
cp scream-sender.conf.example ~/.config/pipewire/pipewire.conf.d/scream-sender.conf
systemctl --user restart pipewire

Multicast, the default:

context.modules = [
    { name = libpipewire-module-scream }
]

Unicast to one receiver, or higher quality:

context.modules = [
    { name = libpipewire-module-scream
      args = { ip = "192.168.1.100" } }
]

context.modules = [
    { name = libpipewire-module-scream
      args = { rate = 96000, format = "S24LE" } }
]

Receiving the stream

Any Scream receiver works. On Linux, the Unix receiver from the main Scream repository (./scream -o pulse); on Windows, ScreamReader from the Scream package. Receivers must open UDP port 4010, and for multicast the network needs working IGMP:

ip route show
sudo ip route add 224.0.0.0/4 dev eth0

Checking it works

pactl list sinks short | grep Scream
paplay --device=Scream /path/to/audio.wav
mpv --audio-device=pipewire/Scream music.mp3
journalctl --user -u pipewire -f | grep -i scream
sudo tcpdump -i any udp port 4010

Troubleshooting

  • Module fails to load — check journalctl --user -u pipewire -f and verify the path with find /usr/lib* -name "*scream*".
  • No audio transmitted — firewall, wrong interface, or no multicast route.
  • Dropouts — network jitter; prefer wired. Default 48 kHz / 16-bit / stereo is about 1.5 Mbit/s and higher settings scale proportionally.

Known issues: short WAV files may carry slight noise depending on the source, and PipeWire < 1.0 is untested.
